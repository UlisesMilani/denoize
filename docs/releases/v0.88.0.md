# denoize v0.88.0

v0.88.0 implements Stage 35: bounded, mixture-preserving codec repair and
bandwidth-extension candidates for complete mono or stereo music programs.

## Added

- Added a dedicated finite, stateless runtime package-v2 adapter with one
  fixed `[1,C,W]` program input, same-geometry candidate audio, and ordered
  bypass/uncertain/apply probabilities on an authenticated state clock.
- Added `MusicRestorationSession`, task-bound conservative configuration,
  deterministic overlapping-window rendering, minimum apply holds, exact
  source-clock duration/channel preservation, and an explicit correction
  residual.
- Added finite-value, absolute correction, output peak, stereo correlation,
  and Mid/Side energy-ratio gates. Confident clean and uncertain regions receive
  no model correction.
- Added `denoize music-restore`. Candidate WAV, float32 correction WAV, and
  path-free report are mandatory, fully staged before publication, no-clobber by
  default, and committed with the candidate last.
- Added signed task/package/configuration promotion evidence with exact artifact
  BOM, training/evaluation license manifests, objective/listening identities,
  zero restricted-artifact redistribution, and twelve fixed codec, clean,
  mono/stereo, phase, transient, long-form, unseen-genre, and reference strata.
- Added closed evidence/report JSON Schemas, semantic tests, generated CLI
  reference, crate packaging checks, release-asset verification, roadmap status,
  product documentation, and a paper plus immutable artifact/license audit.

## Safety boundary

The output is always labeled a model-generated candidate, never recovered
ground truth. The operation produces no dry stems and applies no creative EQ,
compression, widening, mastering, prompt control, or text-directed generation.
No model or checkpoint is bundled. The exact graph, numerical vectors,
source/checkpoint and inherited artifact identities, licenses, training data,
resource limits, evaluation corpora, and promotion result must authenticate
before program audio is opened.

## Research basis

The evaluation boundary follows the Music Source Restoration task and challenge
(Multi-Mel-SNR, Zimtohrli, FAD-CLAP, instrument strata, and professional
listening), MSRBench's phase-aware warning, Apollo's band-split codec work, and
the long-form restoration results of A2SB. X-LANCE, A2SB, Apollo, SonicMaster,
the official MSR baseline, and MSRKit were audited independently at source,
checkpoint/dependency, and data-license layers. None currently clears the full
denoize redistribution and signed promotion boundary, so v0.88.0 ships no
upstream weights.
