## Highlights

- Added deterministic, read-only execution plans for finite regular-file and
  batch processing. Plans bind portable input/output locators, exact input and
  model fingerprints, the effective recipe/backend/accelerator, audio geometry,
  publication decisions, and admitted resources without creating output,
  journal, lock, catalog, or model-cache state.
- Added optional Ed25519-signed execution receipts after successful output
  publication. Receipts bind the plan identity and actual fingerprints of every
  processed or exactly skipped output; a failed or cancelled batch never emits
  a successful receipt.
- Added offline receipt verification against a separately supplied public key
  or explicit rotation/revocation policy. Verification authenticates the
  receipt before resolving and independently hashing every output beneath the
  selected root.
- Added owner-private receipt key generation, public-key recovery, trust-policy
  creation, plan export, receipt publication, and verification to both the CLI
  and desktop app.
- Published six bounded, fail-closed JSON Schemas for plans, receipts, receipt
  keys, trust policies, and verification reports in release assets and the
  crates.io package.

## Compatibility

- Existing processing defaults are unchanged. Plans and receipts currently
  cover finite regular-file inputs only; stdin, streaming, and checkpoint-bound
  receipts remain reserved for Stage 12.
- Planning is side-effect free but is an executable preflight rather than a
  filename estimate: it opens and hashes inputs, performs bounded decode and
  metadata checks, prepares the selected backend/model, validates the encoder,
  and admits the conservative resource request.
- Receipt secret-key JSON is intentionally unencrypted. denoize creates it
  without clobbering and requires owner-only Unix permissions or a protected
  Windows DACL, but backups, process memory, allocator copies, and crash dumps
  remain the operator's responsibility.
- Audio and receipt files are separate atomic publications. If a receipt-path
  race occurs after audio commits, denoize preserves the audio, refuses to
  overwrite the competing receipt, and reports the partial publication state.
- Restartable stream checkpoint sessions now release their advisory output
  lock explicitly when the session is dropped. A transient process that
  inherited the underlying descriptor can no longer cause a spurious lock
  conflict for the next session; the checkpoint format is unchanged.
- Receipts prove the authenticated plan and current output bytes; they do not
  prove wall-clock time, execution duration, host identity, or user identity.
  Unknown fields and future execution-document schema versions fail closed.
- Because the denoize package version participates in the unchanged v3
  batch-resume recipe hash, v0.58 records are reported as `recipeChanged` after
  upgrading to v0.59. Existing outputs remain untouched unless `--force` is
  supplied. Regenerate once with `--force` to migrate the saved recipes;
  subsequent identical v0.59 runs skip normally.
