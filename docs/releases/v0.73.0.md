# denoize v0.73.0

## Highlights

- Added signed runtime-model package v2 while retaining complete v1 loading,
  inspection, creation, and execution compatibility.
- Added a deterministic ordered component container for one to eight ONNX
  precision profiles, a consolidated license notice, provenance JSON, and a
  separate numerical-vector document for every profile. Scripts, commands,
  archives, extraction, path traversal, external-data lookup, and unreferenced
  components are rejected.
- Added closed named input/output contracts with semantic roles for primary
  audio, far-end reference, target-speaker enrollment, microphone geometry,
  recurrent state, controls, masks, and diagnostics. Names, element types,
  ranks, fixed dimensions, state pairing, channels, geometry, and latency are
  authenticated before inference.
- Added per-profile CPU, Metal, and CUDA allowlists and bounded host/device
  resource contracts. The default remains float32 and CPU-compatible;
  accelerator-only optimized profiles retain that portable fallback.
- Added signed numerical conformance vectors with bounded case, tensor, and
  element counts. The selected runtime must reproduce every declared output
  type, shape, and value within signed absolute/relative tolerances before it
  can process user audio.
- Added CLI package-v2 creation and detailed inspection, Desktop authenticated
  package details, Draft 2020-12 schemas, schema parity tests, documentation,
  and release assets.

## Compatibility

- Existing `.dmp` v1 packages remain byte-for-byte compatible and continue to
  use the original command and generic waveform adapter.
- Package v2 is additive. The generic ONNX adapter executes only one-audio-
  input/one-audio-output float32 waveform graphs in the existing
  `[batch,samples]` or `[batch,channel,samples]` layout. Richer named graphs
  fail with a dedicated-adapter requirement instead of guessing semantics.
- v0.73.0 application updates accept exact transitions from v0.71.0 and
  v0.72.0, with authenticated offline rollback assets for both.

## Safety boundary

- The public key remains an explicit out-of-package trust decision. Every
  manifest, framing length, component size/digest, and selected component is
  reverified; same-inode mutation and no-clobber publication remain enforced.
- Provenance records exact source/checkpoint/conversion identities and all
  disclosed training datasets, but authentication is not an independent audit
  of the truth or legal sufficiency of those claims.
- Numerical vectors establish runtime/package compatibility, not model quality.
  Per-stage reference metrics, stratified listening, semantic/speaker gates,
  and undamaged-input bypass tests remain mandatory.
