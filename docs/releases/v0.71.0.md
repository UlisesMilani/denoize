## Highlights

- Added portable `denoize-project-v1` manifests with exact source fingerprints,
  decoded-presentation geometry, channel maps, padding, adjacent crossfades,
  settings, DAW presets, signed model packages, plans, receipts, and license
  references.
- Added deterministic bounded timeline assembly to 32-bit floating-point WAV.
  CLI, Rust library, Desktop, batch, and durable watch automation share the same
  linear edit semantics, validation, output collision checks, and atomic
  publication path.
- Added exact project execution plans and project-domain Ed25519 receipts. A
  reviewed plan must equal the independently reconstructed current plan;
  verification authenticates the signer, optionally binds that plan, and
  rehashes the rooted published output.
- Added deterministic `.dpb` offline bundles with complete inspection and
  no-clobber staged-directory import. Settings, presets, evidence, source
  licenses, model public keys, plans, and receipts are included by default;
  source and model payloads require explicit positive aggregate byte limits.
- Added ten closed Draft 2020-12 project schemas, parser/fuzz coverage, runtime
  schema generation tests, release asset verification, and crates.io package
  coverage for the complete project contract.

## Compatibility

- Project schema v1 and `.dpb` bundle v1 are new. Older denoize versions do not
  understand them. Unknown fields, future schema versions, unsupported graph
  shapes, and future bundle records fail closed.
- Assembly currently supports an ordered linear timeline with one exact source
  timebase, explicit channel maps, silence padding, and only adjacent unpadded
  crossfades. It publishes a 32-bit floating-point WAV; it does not resample or
  implement arbitrary overlapping/branching edit graphs.
- v0.71.0 application updates accept exact transitions from v0.69.0 and
  v0.70.0. Each supported platform ships an authenticated offline recovery
  bundle for both source versions.
- Because the denoize package version participates in the unchanged v3
  batch-resume recipe hash, v0.70.0 records are reported as `recipeChanged`
  after upgrading. Existing outputs remain untouched unless `--force` is
  supplied.

## Safety and portability boundary

- Every manifest locator must remain below one canonical project root and
  resolve through the expected regular file. Sources and referenced artifacts
  are rehashed before use; sources are also fully decoded in bounded blocks to
  verify sample rate, channel count, and exact presentation length.
- Missing-source relocation changes only a newly published manifest and
  requires the replacement bytes and complete presentation geometry to match.
  Source audio is never modified.
- Assembly preflights the complete manifest and referenced contracts before
  staging output, retains one decoder block plus bounded adjacent crossfade
  tails, verifies the encoded WAV, and only then commits. Output paths cannot
  collide with the manifest or any project artifact.
- Bundle inspection authenticates every length-delimited byte and parses every
  embedded document without changing state. Import publishes only to an absent
  destination directory. No operation silently replaces existing data unless
  its explicit CLI replacement option permits it.
