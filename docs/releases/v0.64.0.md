## Highlights

- Added bounded asynchronous sinc resampling between independent capture and
  playback clocks. A bounded PI controller makes small ratio corrections to
  hold the playback queue near its target without abrupt timebase resets.
- Added finite exponential-backoff recovery for live device and stream
  failures. Named devices are reacquired by an unambiguous exact name,
  duplicate names fail safely, and every recovered generation cold-resets
  causal state and primes playback before audio resumes.
- Made capture and playback callbacks non-waiting and expanded CLI NDJSON and
  desktop diagnostics with queue depth, processing and device latency,
  estimated total latency, drift correction, underrun/overflow/drop counts,
  reconnect attempts, and device generation.

## Compatibility

- Existing file, batch, and bounded file-streaming outputs, v3 batch journals,
  v1/v2 stream checkpoints, execution plans, signed receipts, and managed
  models remain compatible. Live-capable backends remain Classical, RNNoise,
  and GTCRN.
- Existing live invocations use automatic queue targeting, a 2,500 ppm drift
  bound, and a 30-second recovery window. Set `--max-drift-ppm 0` to retain
  nominal-rate conversion without clock correction, or
  `--reconnect-timeout 0` to restore immediate failure. Reported latency is an
  engineering estimate rather than a hardware loopback guarantee.
- Because the denoize package version participates in the unchanged v3
  batch-resume recipe hash, v0.63 records are reported as `recipeChanged` after
  upgrading to v0.64. Existing outputs remain untouched unless `--force` is
  supplied. Regenerate once with `--force`; subsequent identical v0.64 runs
  skip normally.
