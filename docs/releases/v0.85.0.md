# denoize v0.85.0

v0.85.0 implements the safe durable baseline of Stage 32: a closed,
content-addressed project/timeline v2 graph with rational time, deterministic
non-linear rendering, append-only edit history, complete cache identities,
explicit-loss interchange, and detached signed edit provenance.

## Added

- Added `denoize-project-v2`, with portable external/embedded source records,
  authenticated model references, stable IDs and revisions, exact rational
  time/parameters, arbitrary clip placement and overlap, nested graphs, tracks,
  nested buses, fades/transitions, immutable effect revisions, step/linear
  automation, and repair masks.
- Added `denoize project v2 migrate`, `inspect`, and `validate`. V1 migration is
  additive and never modifies the source manifest; validation decodes current
  sources and authenticates signed model packages against separately
  fingerprinted public keys.
- Added `denoize project v2 render` with current-byte source verification,
  source resampling, bounded memory/output frames, stable ID-order scalar `f64`
  accumulation, scheduler-independent PCM, and atomic WAV/FLAC/Ogg Opus/MP3/M4A
  publication.
- Added executable `gain-v1`, `polarity-v1`, and `repair-mask-v1` effects.
  `denoise-recipe-v1` is typed and authenticated but fails explicitly until the
  existing execution-plan renderer is selected.
- Added a Rust append-only journal API for clip insert/remove/move/split/join,
  effect-chain/revision edits, typed inverse undo/redo, hash-linked NDJSON,
  recoverable final-record truncation, replay, atomic append replacement, and
  root/prefix-bound checkpoints. Added read-only CLI journal inspection.
- Added cache request, key, record, and verification APIs. Cache identity binds
  graph topology, sources, immutable effects, authenticated model package/key/
  license identities, runtime/determinism/jobs, floating-point contract, output
  format/geometry/bitrate, metadata, and provenance policy. Hits rehash current
  dependencies and both cached output bytes and decoded PCM.
- Added explicit-loss OTIO/OTIOZ/OTIOD/ADM-BW64 assessment, plain `.otio`
  export, and bounded read-only `.otio` inspection. External free-form effects
  never become executable nodes.
- Added detached Ed25519 project edit assertions targeting C2PA 2.4 action
  vocabulary. Signing rehashes sources, authenticates signed model packages and
  their separately fingerprinted keys/license identities, projects every action
  in the selected nested-graph closure onto the root clock with its owner graph
  ID, and binds output bytes and decoded PCM; verification authenticates the
  signature, declared audio format, exact bytes, and PCM. Ogg Opus has an explicit
  detached carrier.
- Added 13 closed JSON schemas, Rust API/CLI tests, real-WAV overlap and
  scheduler-equality tests, journal recovery/inverse tests, cache-integrity tests,
  provenance tamper/format tests, schema traversal tests, documentation, research
  status, and roadmap status.

## Determinism and safety boundary

Manifest and effect digests use domain-separated canonical JSON. IDs, revisions,
ranges, references, graph/bus cycles, nesting depth, counts, locators, JSON-safe
integers, and resource ceilings are validated before rendering or publication.
Revision 1 has no parent, later roots require a parent digest, and immutable
effect histories must be contiguous from revision 1.
Unknown fields and future nodes fail closed. `--jobs` participates in runtime
and cache identity while summation stays in the same stable scalar order.
External source media is never modified or deleted by an edit, undo, checkpoint,
interchange, cache, or provenance operation.

## Deliberate limitations

- The v2 renderer does not execute `denoise-recipe-v1`; an independently
  verified execution plan remains required for restoration DSP.
- v0.85.0 authors plain `.otio` only. OTIOZ/OTIOD packaging, bounded media-copy
  import, and ADM/BW64 object/bed authoring remain future gated work.
- OTIO export is editorial and loss-reporting. Arbitrary timing, transitions,
  executable effects, automation, repair masks, model bindings, bus/nested graph
  semantics, and provenance remain in namespaced metadata or the denoize sidecar
  as explicitly reported.
- Provenance is a C2PA-2.4-targeted signed handoff, not a complete embedded C2PA
  credential. No output container claims an embedded manifest store in this
  release, and signer identity/disclosure remains the caller's responsibility.
- Journal mutation/checkpoint and cache record/hit operations are public Rust
  APIs; the v0.85.0 CLI exposes journal inspection and cache-key construction.
  Journal mutation is a single-writer contract, so callers must serialize writers
  rather than treating atomic file replacement as a multi-process lock.
- Cache records are not signed. Verification is for a trusted local cache
  namespace, not an attacker-controlled store able to replace both record and
  output; distributed cache trust requires an independent signed receipt.

## Release verification

The release workflow validates all Rust targets/features, all 89 JSON contracts,
the generated CLI reference, exact version metadata, crates.io package contents,
release asset inventory/checksums, application-update rollback metadata, SBOMs,
and provenance before publication.
