# denoize v0.90.1

v0.90.1 fixes the `denoize Neural` parameter controls exposed by REAPER and
OSARA on Windows when the managed GTCRN model has not been installed.

## Fixed

- Keep the CLAP audio processor active as a fixed-latency fallback when the
  authenticated neural model cannot be prepared. REAPER can therefore deliver
  changes to Bypass, Mix, Output Gain, and Overload Fallback through the same
  host parameter API used by OSARA.
- Continue to fail neural inference closed: no missing, replaced, redirected,
  or otherwise unverified graph is executed. Audio follows the selected
  overload fallback, which is latency-aligned dry audio by default.
- Avoid queue traffic and false overload accounting while the neural worker is
  unavailable. Installing or repairing the model and then reactivating or
  reloading the effect enables inference.

## Regression coverage

- Added a Windows REAPER 7.79 smoke test that builds the current CLAP plug-in
  with an empty model directory, starts the host with Dummy Audio, plays audio,
  and adjusts all four Neural parameters through OSARA's REAPER API path.
- Added a unit test proving that model initialization failure leaves the
  processor active, honors bypass/mix/gain/fallback changes, emits the declared
  delayed-dry signal, and performs no worker queue traffic.

This release resolves [#215](https://github.com/penguin425/denoize/issues/215).
