## Highlights

- Added bounded, presentation-timeline-aware streaming decode for FLAC,
  Vorbis and Opus, MP3, ADTS AAC, and M4A AAC/ALAC. Checkpoints persist only
  samples that remain after codec delay, granule trimming, and edit-list
  mapping, so resumed output matches uninterrupted processing.
- Added bounded encoded streaming output for WAV, FLAC, Ogg Opus, MP3, M4A,
  and ADTS AAC. Every completed artifact is decoded and verified before atomic
  publication; a failed encode or verification leaves an existing destination
  untouched.
- Added finite stdin/stdout and library `Read`/`Write` spools with explicit
  memory and temporary-space admission. Anonymous streams remain bounded while
  durable restart continues to require regular-file endpoints.
- Added v2 execution plans, signed receipts, and offline verification reports
  for checkpointed streaming jobs. Three fail-closed JSON Schemas are included
  in release assets and the crates.io package.
- Added desktop parity for streaming plans, resume/recovery, encoded output,
  resource admission, and signed receipts.

## Compatibility

- Existing v0.58/v0.59 v1 stream checkpoints, v3 batch journals, and v1
  execution documents remain readable. New streaming plans and receipts use
  separate v2 schemas; unknown future versions are rejected without modifying
  durable state.
- Filesystem processing still requires regular-file inputs and outputs.
  Symlinks resolving to regular files are accepted; FIFOs, directories, and
  devices are rejected. CLI stdin/stdout and library spools are the explicit
  bounded non-seekable paths.
- Anonymous `Read`/`Write` spools are finite but ephemeral: they cannot resume
  after process loss and do not provide filesystem-atomic publication.
- Working-set and temporary-space limits now include retained stream state,
  denoize-owned codec scratch, spool capacity, and requested encoded-output
  capacity. Third-party private allocations and allocator rounding remain
  outside an exact process-RSS guarantee; concurrent workers are admitted
  independently under the process-wide controller.
- Small M4A outputs use a conventional 32-bit `mdat` size and `stco` chunk
  offsets. Outputs that exceed those ranges switch to a reserved 64-bit `mdat`
  size and `co64` offsets without shifting already-written media.
- Because the denoize package version participates in the unchanged v3
  batch-resume recipe hash, v0.59 records are reported as `recipeChanged` after
  upgrading to v0.60. Existing outputs remain untouched unless `--force` is
  supplied. Regenerate once with `--force` to migrate saved recipes;
  subsequent identical v0.60 runs skip normally.
