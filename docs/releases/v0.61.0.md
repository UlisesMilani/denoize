## Highlights

- Added a deterministic, bounded parser-mutation matrix for every supported
  audio container and for execution plans, signed receipts and keys, trust
  policies, and offline model bundles. Minimized fuzz findings must become
  checked-in regressions before they are considered fixed.
- Added scheduled AddressSanitizer/libFuzzer campaigns with pinned harness
  dependencies, checked-in corpora and dictionaries, and finite input, RSS,
  per-case, and campaign limits. The fuzz dependency graph is audited in CI
  and release validation.
- Added a versioned debug/test-only fault protocol around staged-file
  synchronization and publication, batch-journal commits, stream checkpoints
  and signed receipts, and managed-model trust-root updates.
- Added child-process crash/restart tests for every durable publication prefix.
  They require an absent, previous, or complete output; coherent restart state;
  reusable locks; and complete automation records after recovery.
- Staged atomic outputs are now flushed and synchronized before publication,
  making the tested local-filesystem durability boundary explicit.

## Compatibility

- Existing v0.59/v0.60 execution documents, v3 batch journals, and v1/v2
  stream checkpoints remain readable. This release does not introduce a new
  persisted schema or require state migration.
- Optimized release binaries ignore `DENOIZE_INTERNAL_FAULT_V1` completely.
  The protocol is internal to debug/test builds and is not an operational
  failure-injection interface.
- Synchronizing each staged output before rename may add storage latency,
  especially on slow or high-latency filesystems. It does not change output
  bytes or publication semantics.
- Crash and power-loss tests model process loss at acknowledged synchronization
  boundaries on a conforming local filesystem. They do not claim protection
  from faulty hardware, lying drive caches, remote-filesystem semantics, or a
  kernel/filesystem that violates its documented durability behavior.
- Because the denoize package version participates in the unchanged v3
  batch-resume recipe hash, v0.60 records are reported as `recipeChanged` after
  upgrading to v0.61. Existing outputs remain untouched unless `--force` is
  supplied. Regenerate once with `--force`; subsequent identical v0.61 runs
  skip normally.
