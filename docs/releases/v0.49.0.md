## Highlights

- Added a signed, sequence-monotonic model catalog. Remote and local catalog
  updates are accepted only after MiniSign authentication, strict schema
  validation, and rollback/equivocation checks against the durable catalog
  state.
- Added content-addressed provenance for managed model installations, binding
  each artifact to its catalog digest, sequence, signing key, and verified
  installation source. Existing valid cached models acquire provenance lazily.
- Added `denoize models catalog status`, `update`, and `import`, corresponding
  desktop catalog controls, and a dedicated `DENOIZE_MODEL_CATALOG_URL` policy.
  Releases now publish and verify the catalog JSON and detached signature as
  first-class assets.

## Compatibility

- Existing managed model names and aliases remain supported, and local custom
  model paths remain available. Offline mode continues to avoid network access
  and uses the authenticated cached or embedded catalog.
- A mismatched or malformed provenance record now fails managed-model
  verification instead of silently trusting the cached artifact. A verified
  legacy cache without provenance is migrated atomically on first use.
- Because the denoize package version participates in the unchanged v3
  batch-resume recipe hash, v0.48 records are reported as `recipeChanged` after
  upgrading to v0.49. Existing outputs remain untouched unless `--force` is
  supplied. Regenerate once with `--force` to migrate the saved recipes;
  subsequent identical v0.49 runs skip normally.
