# denoize v0.74.0

## Highlights

- Added a deterministic, model-free restoration pipeline with a separate Rust
  API and `denoize restore` CLI surface. The fixed operation order covers
  constrained de-clipping, prediction-residual de-clicking, robust harmonic
  de-hum, finite WPE de-reverberation, and conservative wind/plosive repair.
- Added first-class detect-only operation. Detectors and reports run normally,
  while decoded input PCM is verified bit-exact and no audio destination is
  required.
- Added complete same-length channel/frame RLE repair masks distinguishing
  untouched, context-padded, detected, and actually replaced samples. Overlap
  priority prevents later padding from hiding a detection.
- Added closed path-free restoration reports with domain-separated input PCM
  SHA-256, mask SHA-256, exact geometry, detected/changed counts, confidence,
  energy delta, warnings, canonical operation order, and typed per-operation
  evidence.
- Added Desktop controls for operation selection, detect-only mode, independent
  or multichannel WPE, memory bounds, metadata policy, and no-clobber/replace
  output, with the report and complete mask rendered locally.
- Added Draft 2020-12 report/mask schemas, exact-coverage parity tests, malformed
  request and destination-collision tests, documentation, release assets, and
  crates.io package checks.

## Restoration behavior

- De-hum searches drifting 49–51 and 59–61 Hz harmonic complexes, performs
  robust per-channel sinusoidal regression in half-overlapped blocks, and
  bypasses blocks below the harmonic-support confidence gate.
- De-click uses a frequency-warped AR residual with median/MAD gating and
  bounded forward/backward prediction interpolation. Long or context-starved
  regions remain untouched and are counted as rejected.
- De-clip estimates asymmetric plateaus, rejects pervasive or ambiguous hard
  limiting, and uses a capped analysis-sparse projection while preserving
  reliable context and upper/lower clipping inequalities.
- WPE has explicit independent and up-to-four-channel modes, delayed predictor
  geometry, iteration/regularization/attenuation bounds, exact-length STFT
  synthesis, and fail-safe bypass counts for ill-conditioned bins.
- Wind/plosive processing accepts only short low-frequency bursts that pass
  spectral-ratio, baseline-excess, temporal-modulation, confidence, and optional
  cross-channel coherence gates; persistent bass is not treated as a burst.

## Safety and compatibility

- Restoration preserves decoded sample rate, channel count/order, and frame
  count. It does not use a model, network, randomness, or untrusted command and
  never presents an estimate as recovered ground truth.
- Input, audio output, report, and mask paths must be distinct. Every existing
  destination is rejected before decode unless `--replace` is explicit; each
  artifact is privately staged and independently atomically committed.
- CLI and Desktop check conservative decode/restoration memory before the heavy
  working set. Multichannel WPE rejects more than four channels instead of
  silently changing mode.
- Existing denoising, diagnosis, assessment, model-package v1/v2, DAW, project,
  IPC, update, and automation contracts remain compatible.
- v0.74.0 application updates accept exact transitions from v0.72.0 and
  v0.73.0, with authenticated offline rollback assets for both.

## Evidence boundary

- The deterministic algorithms provide inspectable estimates, not proof of the
  original samples, words, speaker identity, or provenance. Reports expose
  confidence and warnings so uncertain regions can remain untouched.
- Same-build repeated-run determinism is tested. Cross-target floating-point
  comparisons still require numerical tolerance rather than assuming identical
  hardware arithmetic.
- Output encoder quantization occurs after restoration; mask and report counts
  describe the in-memory result before encoding.
