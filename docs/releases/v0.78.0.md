# denoize v0.78.0

v0.78.0 delivers the Stage 28b VST3 reference gate without forking the CLAP
DSP, neural scheduler, state, or trust boundary.

## VST3 3.8 bundles

- Ships ready-to-copy VST3 bundles for Linux x86-64, macOS Intel and Apple
  Silicon, and Windows x86-64, each with a checksum and per-artifact CycloneDX
  SBOM.
- Exposes both stable processors: `denoize` and `denoize Neural`, with their
  existing IDs, parameters, main buses, and Neural reserved reference bus.
- Statically links the exact Rust CLAP entry. The adapter cannot discover or
  substitute a same-named CLAP binary from a host, user, or system path.
- Pins clap-wrapper 0.16.0, CLAP SDK 1.2.6, VST3 SDK 3.8.1, and the four SDK
  submodules by exact commit. Two checked-in patches cover the SDK 3.8.1
  interface rename and remove dynamic CLAP fallback.
- Preserves component/controller state, parameter queues, bypass, bus
  negotiation, suspend/resume, and VST3 latency-change restart through the
  shared CLAP contract.

## Validation and signed host evidence

- Both descriptors pass the pinned official VST3 3.8.1 validator: 94 tests
  passed and zero failed.
- The process-format suite passes all twelve exercised sample rates through
  1,234,567.8 Hz. A separate DAW host-rate boundary now reaches the internal
  bounded resampler without widening the 768 kHz file/offline boundary.
- Linux release modules require a non-executable stack, RELRO, immediate
  binding, resolved native dependencies, and exported VST3/static CLAP entries.
- A pinned Ardour 8.4.0 host process discovers and inserts both descriptors,
  processes them at 48 kHz, checks their 480/11,520-frame latency contracts,
  saves state, reloads it in a fresh host process, processes again, and tears
  down cleanly.
- Publishes the full validator and Ardour logs and a closed
  `denoize-plugin-host-matrix-v1` document binding its SHA-256, source commit,
  dependency revisions, descriptors, counts, exercised frames, lifecycle
  results, and maximum rates.
- A dedicated Sigstore/SLSA bundle signs all three evidence subjects. Final release
  verification authenticates the tag, commit, release workflow, and trusted
  root before publication.

## Scope and compatibility

- Native CLAP remains compatible and still accepts f32/f64 buffers. The pinned
  wrapper exposes f32 VST3 processing and formally reports double precision as
  unsupported; this release does not claim an internal f64 VST3 path.
- Hosts render generic parameter controls. A custom accessible editor remains
  the separate Stage 28c gate.
- The signed matrix proves official-validator compatibility and the named
  Ardour 8.4.0~ds1 observation on Ubuntu 24.04 x86-64. It explicitly records
  that proprietary hosts were not exercised and makes no compatibility claim
  for an unnamed host.
- AUv3 and LV2 remain separate lifecycle, sandbox/worker, validation,
  packaging, and host-matrix gates.
