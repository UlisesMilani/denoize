## Highlights

- Added a bounded, non-destructive desktop preview that renders at most 30
  seconds with the same source fingerprint, backend, resource admission, and
  recipe used by the final job. Users can compare loudness-matched original,
  processed, and removed-noise signals or run a blind A/B test before adopting
  the selected recipe.
- Moved desktop preview, file, and batch processing into supervised child
  processes with authenticated bounded progress messages, shared
  cancellation/commit fences, platform resource containment, and fail-closed
  cleanup. Owner-private recovery records can retry an interrupted request or
  discard only an exact verified denoize stage without deleting an existing
  output or restart journal.
- Added bounded redacted diagnostic export, stable structured error codes,
  Japanese and English localization, complete keyboard and ARIA navigation,
  visible focus, reduced-motion and forced-colors behavior, and a real-WebView
  accessibility regression gate.

## Compatibility

- Existing presets, v3 batch journals, v1/v2 stream checkpoints, execution
  plans, and signed receipts remain compatible. Desktop recovery and preview
  records are new internal schemas; unknown or malformed records fail closed
  without modifying user output.
- Desktop preview is intentionally limited to 30 seconds and never publishes
  an output. Final file and batch jobs now always use a supervised worker, but
  their output bytes, atomic publication rules, and resume contracts are
  unchanged.
- Because the denoize package version participates in the unchanged v3
  batch-resume recipe hash, v0.61 records are reported as `recipeChanged` after
  upgrading to v0.62. Existing outputs remain untouched unless `--force` is
  supplied. Regenerate once with `--force`; subsequent identical v0.62 runs
  skip normally.
