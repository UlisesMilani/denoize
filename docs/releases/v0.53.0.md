## Highlights

- Added the stable `denoize-automation-v1` snapshot for catalog and trust
  identity, model health, installation provenance, cache diagnostics, and the
  batch recipe ABI. The CLI and desktop export the same network-free document.
- Added the stable `denoize-cli-output-v1` contract to file, streaming, and
  batch JSON/NDJSON output, including explicit event and mode discriminators
  and the exact finite-file recipe digest where one exists.
- Added both versioned JSON Schemas to GitHub release assets and crates.io
  packages, with tagged-source verification before release publication.

## Compatibility

- Existing processing JSON records gain additive `schema`, `schema_version`,
  and `recipe` fields. File and streaming results also gain `event` and `mode`.
  Consumers must ignore unknown fields added within a schema version; removing
  a field or changing its type or documented value requires a new schema.
- Automation snapshot capture uses authenticated local or embedded state and
  never opens a network connection. URLs omit credentials, query strings, and
  fragments. Capture or serialization failure produces no partial JSON output.
- Batch summaries and stateful streaming results retain the recipe ABI identity
  but use a `null` recipe digest because they do not represent one finite-file
  processing recipe.
- Because the denoize package version participates in the unchanged v3
  batch-resume recipe hash, v0.52 records are reported as `recipeChanged` after
  upgrading to v0.53. Existing outputs remain untouched unless `--force` is
  supplied. Regenerate once with `--force` to migrate the saved recipes;
  subsequent identical v0.53 runs skip normally.
