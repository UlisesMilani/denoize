## Highlights

- Added CycloneDX 1.7 SBOMs for all 14 installable release artifacts: four
  CLI archives, eight desktop packages, the exact crates.io archive, and the
  closed-network model bundle.
- Added GitHub/Sigstore build provenance for every installable artifact and a
  separately attested, deterministic release-evidence archive that binds each
  artifact and SBOM to its exact SHA-256 and size.
- Added an offline verifier and versioned JSON Schema. The verifier authenticates
  the evidence archive before extraction, enforces repository, tag, source
  commit, release-workflow, and GitHub-hosted-runner policy, and then checks all
  artifact, SBOM, checksum, provenance, and crates.io source bindings.
- The exact pre-attested `.crate` is now rebuilt from its embedded lockfile
  before publication, compared byte-for-byte, and checked against the checksum
  reported by the crates.io API before the GitHub draft can become public.
- Release-producing GitHub Actions are pinned to immutable commit SHAs and Rust
  is pinned to the repository's 1.96.0 MSRV toolchain.

## Compatibility

- Runtime audio processing and existing command defaults are unchanged. This
  release hardens only packaging, provenance, publication, and verification.
- SBOM dependency inventories conservatively follow the applicable tagged Cargo
  and npm lockfiles. A target may omit an optional locked package even though
  that package remains listed in its inventory.
- Sigstore bundles and the trusted-root snapshot are intentionally separate
  from the deterministic evidence archive because signing timestamps and
  certificate material vary. For a new offline import, obtain the trusted root
  independently rather than trusting the copy from the same artifact mirror.
- GitHub provenance establishes the tagged source, workflow, and hosted runner;
  it does not claim byte-for-byte reproducibility for platform-signed installers
  without their private signing keys.
- Because the denoize package version participates in the unchanged v3
  batch-resume recipe hash, v0.57 records are reported as `recipeChanged` after
  upgrading to v0.58. Existing outputs remain untouched unless `--force` is
  supplied. Regenerate once with `--force` to migrate the saved recipes;
  subsequent identical v0.58 runs skip normally.
