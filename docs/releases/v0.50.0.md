## Highlights

- Added `denoize models doctor`, `repair`, and `prune` for cache-wide diagnosis,
  atomic recovery, and conservative cleanup of interrupted downloads, stale
  provenance, and fully proven orphaned packages.
- Added the same health report, targeted repair, cancellation, prune preview,
  and prune apply workflow to the desktop model manager.
- Hardened crates.io packaging so frontend dependency trees cannot leak into
  the published archive; dry-run publishing now verifies this invariant.

## Compatibility

- `models doctor` is read-only. `models prune --dry-run` previews every removal,
  and apply mode retains arbitrary files, unknown provenance, symlinks, devices,
  FIFOs, and any package whose denoize ownership cannot be proven.
- `models repair` preserves the current artifact unless a locally rebuilt
  provenance record or fully downloaded, size/SHA-256-verified replacement can
  be committed atomically. Offline repair never opens a network connection.
- Because the denoize package version participates in the unchanged v3
  batch-resume recipe hash, v0.49 records are reported as `recipeChanged` after
  upgrading to v0.50. Existing outputs remain untouched unless `--force` is
  supplied. Regenerate once with `--force` to migrate the saved recipes;
  subsequent identical v0.50 runs skip normally.
