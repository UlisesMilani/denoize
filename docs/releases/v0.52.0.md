## Highlights

- Added deterministic signed offline model bundles for closed networks. Each
  `.dmb` carries the authenticated catalog and signature, the trust root,
  exact model artifacts, license notices, and source provenance.
- Added `denoize models bundle create`, `inspect`, and `import`, plus matching
  desktop inspection and import controls. Inspection is read-only; import
  validates the complete bundle before atomically installing any model.
- Advanced the embedded catalog to sequence 2 with authenticated offline-bundle
  metadata for the managed GTCRN DNS3 model. Releases now build, checksum,
  upload, import, and reverify the complete offline bundle before publication.

## Compatibility

- Existing signed-catalog updates and individual local artifact imports remain
  supported. Bundle inputs and model storage must resolve to regular files and
  directories; symbolic-link model directories, devices, FIFOs, duplicate
  component names, expired or rolled-back catalogs, and mismatched content are
  rejected before persistent state changes.
- The v0.52 release adds `denoize-models-v0.52.0.dmb` and its SHA-256 sidecar.
  Closed-network deployments can transfer those two assets and inspect or
  import the bundle without opening a network connection.
- Because the denoize package version participates in the unchanged v3
  batch-resume recipe hash, v0.51 records are reported as `recipeChanged` after
  upgrading to v0.52. Existing outputs remain untouched unless `--force` is
  supplied. Regenerate once with `--force` to migrate the saved recipes;
  subsequent identical v0.52 runs skip normally.
