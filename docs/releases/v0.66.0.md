## Highlights

- Added durable local watch-folder automation to the CLI and desktop app. The
  portable polling engine accepts a supported regular audio file only after its
  filesystem identity, length, modification stamp, and SHA-256 content remain
  unchanged for the configured settle interval.
- Added atomic single-writer state, stable processing-template identity,
  bounded retries with exponential backoff, crash recovery, collision-safe
  relative output names, signed execution receipts, and verified quarantine
  evidence. Interrupted work is retried or reconciled without guessing which
  publication step completed.
- Added bounded cycle, state, and quarantine JSON schemas to the public
  automation contract and release assets. Watch mode uses normal per-input
  resource admission and an isolated per-file worker in the desktop app.

## Compatibility

- Watch mode is opt-in; existing file, batch, streaming, live-device,
  custom-model, resume, checkpoint, receipt, and output contracts are unchanged.
  It is intentionally sequential. Input and output trees must be separate,
  directory links are not traversed, and watch state, receipts, and quarantine
  paths must remain below the output root.
- The receipt secret key is mandatory, unencrypted, and must remain outside the
  watched trees. A changed processing template, signing identity, or explicitly
  selected model artifact requires a fresh watch-state path; existing outputs
  and state are preserved on mismatch.
- Because the denoize package version participates in the unchanged v3
  batch-resume recipe hash, v0.65 records are reported as `recipeChanged` after
  upgrading to v0.66. Existing outputs remain untouched unless `--force` is
  supplied. Regenerate once with `--force`; subsequent identical v0.66 runs
  skip normally.

## Safety boundary

- The watcher never follows directory symlinks or accepts FIFOs, devices, or
  non-regular inputs. It verifies a settled source again at publication or
  quarantine boundaries and never replaces an unrelated destination.
- Polling, tracked candidates, traversal depth, retries, backoff, state,
  receipts, and quarantine evidence are explicitly bounded. A stable completed
  input is checked through filesystem metadata rather than re-hashed on every
  poll; the operator remains responsible for protecting the receipt secret key
  and the configured input/output roots from hostile writers.
