## Highlights

- Added `denoize recommend` and matching Rust APIs to analyze a bounded signal
  prefix and rank locally runnable backend, preset, mode, strength, and
  accelerator settings without contacting a service or updating model state.
- Added the stable `denoize-recommendation-v1` report and JSON Schema. Reports
  contain content-derived signal metrics, one read-only hardware snapshot,
  local model/runtime eligibility, CPU and GPU reservation estimates, stable
  reason codes, and explicit command arguments.
- Added optional on-device calibration using a fixed hash-identified Classical
  Hi-Fi fixture, one warmup, and one to nine measured runs. Reports retain the
  raw timings and median baseline headroom while clearly identifying
  per-backend results as cost-class estimates rather than direct benchmarks.
- Added the recommendation analysis and apply workflow to the desktop app,
  including goal, calibration, process-memory, GPU-memory, accelerator, and
  deterministic controls.
- Published the recommendation Schema in GitHub release assets and the
  crates.io package, with tagged-asset equality verification.

## Compatibility

- Recommendation is additive and does not change existing processing defaults.
  It accepts regular filesystem inputs; FIFOs, directories, devices, and stdin
  are rejected. Symlinks resolving to regular files remain accepted.
- WAV, FLAC, and Ogg Vorbis recommendations decode only the bounded analysis
  prefix. Other supported containers use their existing whole-file decoder
  under the supplied memory ceiling before only the bounded prefix is analyzed.
- Backends requiring a caller-supplied model path remain visible but ineligible
  because recommendation reports never serialize model or input paths. Managed
  models are verified read-only without creating catalog or provenance state.
- GPU eligibility uses a conservative session estimate and any reported device
  memory limit. The read-only probe does not create or test a CUDA kernel cache;
  actual processing revalidates cache writability and model preparation.
- Calibration timings vary with system load. The workload bytes and hash are
  stable, but candidate realtime headroom is an explainable cost-class estimate,
  not proof that a neural backend ran at the reported speed.
- Because the denoize package version participates in the unchanged v3
  batch-resume recipe hash, v0.56 records are reported as `recipeChanged` after
  upgrading to v0.57. Existing outputs remain untouched unless `--force` is
  supplied. Regenerate once with `--force` to migrate the saved recipes;
  subsequent identical v0.57 runs skip normally.
