## Highlights

- Added signed, self-describing `.dmp` runtime model packages for
  operator-supplied generic ONNX models. A bounded length-delimited container carries a
  strict manifest, its Minisign signature, the authenticated model, and the
  required license notice without extracting untrusted files.
- Bound package identity, revision, SPDX license, sample rate, waveform
  frontend, float32 tensor geometry, resource reservations, and accelerator
  allowlists to a separately supplied trust key. The runtime rejects external
  tensor sidecars and checks the signed graph contract before inference.
- Integrated package creation, inspection, license display, selection, and
  authenticated identity reporting across the CLI, desktop app, JSON/config
  surfaces, resume fingerprints, resource planning, and public library APIs.
  The v1 package schema is also published as a release asset.

## Compatibility

- Existing raw ONNX model workflows remain supported. Raw-model and
  signed-package options are mutually exclusive; when a package is selected, its
  authenticated sample rate, resource reservations, tensor contract, and
  accelerator allowlist are authoritative. Version 1 packages support the
  generic ONNX waveform runtime and require CPU in the signed allowlist.
- Existing file, batch, bounded streaming, live-device, managed-model,
  execution-plan, signed-receipt, and checkpoint formats remain compatible.
- Because the denoize package version participates in the unchanged v3
  batch-resume recipe hash, v0.64 records are reported as `recipeChanged` after
  upgrading to v0.65. Existing outputs remain untouched unless `--force` is
  supplied. Regenerate once with `--force`; subsequent identical v0.65 runs
  skip normally.

## Trust boundary

- The package signing key is never embedded in the package. Modern Minisign
  signatures, exact component sizes and SHA-256 digests, strict manifest
  fields, authenticated ONNX byte ranges, and whole-package resume fingerprints
  fail closed when package bytes or contracts change.
- Signed CPU/GPU reservations are conservative admission values for each
  session and worker, not portable exact-RSS guarantees for third-party
  runtimes or allocators.
