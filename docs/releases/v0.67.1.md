## Highlights

- Fixed the GitHub Release updater manifest race exposed by v0.67.0. A
  downstream aggregation job now waits for every desktop target and publishes
  one complete ten-platform `latest.json` instead of accepting whichever
  matrix job uploads last.
- The aggregator verifies every updater payload and signature is uploaded and
  non-empty, checks SHA-256 signature digests, pins payload URLs to this
  repository's release-assets API, writes the complete manifest atomically,
  and then replaces the draft release asset.
- Release evidence and final asset verification now depend on the aggregated
  updater manifest, so an incomplete or inconsistent updater cannot make the
  draft release public.

## Compatibility

- Audio processing, library APIs, CLI behavior, desktop projects, updater
  payloads, and the ten supported updater platform identifiers are unchanged
  from v0.67.0.
- Because the denoize package version participates in the unchanged v3
  batch-resume recipe hash, v0.67.0 records are reported as `recipeChanged`
  after upgrading to v0.67.1. Existing outputs remain untouched unless
  `--force` is supplied. Regenerate once with `--force`; subsequent identical
  v0.67.1 runs skip normally.

## Safety boundary

- Missing, duplicate, empty, non-uploaded, cross-repository, or digest-mismatched
  updater assets stop the release before evidence generation. The GitHub
  release remains a draft on any failure.
