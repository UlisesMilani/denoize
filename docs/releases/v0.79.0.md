# denoize v0.79.0

v0.79.0 completes the native CLAP portion of Stage 28c with one accessible,
bounded custom editor shared by the existing DSP and Neural descriptors. Audio
algorithms, plug-in IDs, parameter IDs, port layouts, latency policies, and
portable state schemas remain unchanged.

## Accessible native editor

- Added the `denoize-plugin-editor` workspace crate with native embedded X11,
  Win32, and Cocoa child windows. Floating and Wayland custom windows are
  rejected so hosts can retain their generic parameter editor.
- Exposed every existing parameter as a deterministic high-contrast toggle,
  slider, or choice with a visible value and focus indicator. Tab/Shift+Tab,
  arrows, Page Up/Down, Home/End, Space/Enter, pointer drag, click, and wheel
  paths update the same model.
- Added AccessKit trees and native AT-SPI, UI Automation, and NSAccessibility
  adapters with names, values, ranges, focus, and supported actions.
- Bounded editor state to atomics, 128 queued gestures, at most 63 coalesced
  overflow values, and fixed window limits. Host-originated values never feed
  automation back to the host.
- Added a resumable Begin → Value → End writer. A full host event buffer pauses
  at the exact unwritten stage without duplicating Begin or applying a value
  twice on the next flush.

## Host ABI and lifecycle

- Added a local standard `clap.gui` vtable bridge for the pinned Clack 0.1.1
  release. It preserves Clack's checked instance dispatch while returning the
  actual failure result from `get_size`, `set_size`, and `set_parent` instead of
  an outer `Option` success.
- Duplicate creation/parenting, show-before-parent, invalid scale, undersized
  host offers, and out-of-range size requests fail closed. Repeated show/hide
  and destroy are safe.
- Window, accessibility, rendering, and host callback errors stay on the main
  thread and do not change audio activation, processing, state, or the generic
  `clap.params` fallback.

## Verification and release evidence

- 13 CLAP unit tests pass with one explicit managed-model performance test
  ignored in the ordinary profile; 11 editor model/layout/render/accessibility/
  lifecycle tests pass.
- The editor crate type-checks for Windows x86-64, macOS x86-64, and macOS
  arm64. Linux release linkage retains a non-executable stack, RELRO,
  BIND_NOW, resolved libraries, and `clap_entry`.
- The pinned official CLAP validator reports exactly 81 results: 68 success,
  13 capability skips, and zero failures, crashes, or warnings.
- A real clack-host 0.1.1 process embeds and renders both editors in baseview
  X11 parents under Xvfb, injects an XTEST bypass click, receives exactly one
  three-event automation gesture per descriptor, and completes the resize and
  lifecycle contract.
- The release publishes the raw host report and a closed
  `denoize-plugin-editor-evidence-v1` JSON document. Their shared Sigstore
  attestation binds the v0.79.0 tag, source commit, release workflow, trusted
  root, per-descriptor observations, report size, and SHA-256.

## Limits

- Signed real-host editor evidence is Ubuntu 24.04 X11 x86-64. Windows and
  macOS native adapters are compile-checked but no proprietary host is claimed.
- Wayland and floating custom windows are unsupported; host generic parameters
  remain available.
- VST3 custom-view support is not inferred from this CLAP gate. The VST3 host
  matrix continues to set `custom_editor` false until a native VST3 host opens
  and exercises the projected view.
- AUv3 and LV2 remain the separate Stage 28d and 28e gates.
