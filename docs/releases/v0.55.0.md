## Highlights

- Added process-wide resource admission for denoize-owned RAM, staged-output
  bytes, CPU workers, GPU workers, and conservative GPU/model memory through a
  shared `ResourceGovernor` used by the library, CLI, and desktop app.
- Added CLI controls for `--max-process-memory`, `--max-temp-space`,
  `--max-gpu-memory`, and `--max-gpu-jobs`. Batch workers wait until their
  complete resource request fits atomically instead of oversubscribing one
  dimension while another is exhausted.
- Added opt-in CLI child isolation with `--isolate`. Unix children use an
  `RLIMIT_AS` address-space ceiling when process memory is configured; Windows
  children use a Job Object process-memory ceiling. A failed child cannot
  publish its staged output.
- Applied the same cooperative accounting to single-file, batch, WAV streaming,
  live, and desktop processing, including retained metadata, loaded model
  sessions, and conservative encoded-output expansion.

## Compatibility

- Existing commands gain no process RAM, temporary-byte, or GPU-memory ceiling
  unless one is configured. Accelerated work is limited to one GPU job by
  default; raise `--max-gpu-jobs` explicitly when the device and configured
  memory budget can support more concurrency.
- Cooperative limits account for denoize-owned capacities and declared codec or
  model allowances. They are not allocator-exact RSS, filesystem quotas, or
  driver-reported VRAM, and private third-party allocations can remain outside
  them. Use CLI `--isolate` for a hard child-process boundary; desktop jobs stay
  in-process.
- `--max-temp-space` is an aggregate reservation plus a final staged-length
  check, not a filesystem quota. Output publication remains transactional when
  admission, decoding, processing, or child execution fails.
- The new desktop configuration fields and CLI flags are additive and do not
  change audio recipe identity. Resource availability can change scheduling or
  reject a run, but not the samples produced by an admitted deterministic job.
- Because the denoize package version participates in the unchanged v3
  batch-resume recipe hash, v0.54 records are reported as `recipeChanged` after
  upgrading to v0.55. Existing outputs remain untouched unless `--force` is
  supplied. Regenerate once with `--force` to migrate the saved recipes;
  subsequent identical v0.55 runs skip normally.
