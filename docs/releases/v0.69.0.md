## Highlights

- Added one reproducible, licensed-corpus evaluation contract shared by the
  Rust library, `denoize evaluate`, the Desktop Evaluation evidence page, and
  CI. Corpus manifests pin source revisions, licenses, preparation, checksums,
  recipes, thresholds, and regression tolerances without shipping restricted
  audio.
- Added signed release evidence for objective and perceptual quality, decoded
  output integrity, and performance. Reports bind the exact inputs, model,
  environment, timing scope, output fingerprints, and any required human
  listening decision.
- Added fail-closed verification and baseline comparison. Verifiers
  authenticate the evidence and recompute threshold outcomes, aggregate timing
  statistics, output ratios, geometry, and acceptance decisions before a
  regression gate can pass.
- Added six Draft 2020-12 schemas for corpus, corpus verification, signed
  evaluation, verification, comparison, and listening-result documents. The
  release workflow ships and verifies all six schemas.

## Compatibility

- Evaluation schema v1 is new in this release. Older denoize versions do not
  understand these documents; future or unknown fields and versions fail
  closed.
- Release evaluations allow only deterministic denoize recipes and CPU or
  automatic accelerator selection. SGMSE recipes require a pinned JSON-safe
  seed; recipes for deterministic non-SGMSE backends reject an irrelevant
  seed.
- Baseline comparison requires the same manifest, corpus cases, inputs,
  regression policy, recipe, model, hardware/runtime environment, and timing
  scope. Performance numbers from different machines are intentionally not
  comparable.
- Because the denoize package version participates in the unchanged v3
  batch-resume recipe hash, v0.68.0 records are reported as `recipeChanged`
  after upgrading to v0.69.0. Existing outputs remain untouched unless
  `--force` is supplied. Regenerate once with `--force`; subsequent identical
  v0.69.0 runs skip normally.

## Evidence and security boundary

- Manifests cannot execute commands. Every corpus and model path must remain
  beneath its declared root and resolve through regular non-symlink files;
  byte length, SHA-256, immutable revision, decoded geometry, and post-use
  fingerprints are checked.
- Evaluation evidence uses owner-controlled Ed25519 receipt keys under a
  separate signature domain. A receipt signature cannot be replayed as an
  evaluation signature, and trust keys remain independently distributed.
- Required listening evidence is cryptographically bound to the corpus,
  manifest, and protocol. Signed results contain the decision and aggregate
  score, not listener identities or source audio.
- A failed threshold or listening decision is written atomically as signed
  negative evidence before the command exits unsuccessfully. Existing output
  is never replaced without an explicit overwrite request.
- JSON floating-point round trips are signature-tested, and comparison rejects
  changed or internally inconsistent measurements instead of trusting stored
  pass/fail fields.
