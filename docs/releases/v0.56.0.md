## Highlights

- Extended bounded `--stream` processing from WAV to native FLAC and Ogg
  Vorbis regular-file inputs. Streams produce an atomic 32-bit float WAV and
  support the stateful Classical, RNNoise, and GTCRN backends in both the CLI
  and desktop app.
- Added durable `--stream --resume` checkpoints. A private append-only journal
  and interleaved PCM spool are synchronized at bounded frame intervals, then
  used to replay decoder and backend state before processing continues from the
  last durable boundary.
- Bound each checkpoint to the exact opened input, processing recipe, model,
  source codec and geometry, and block size. Changed evidence is preserved and
  rejected unless `--force` explicitly starts a new stream.
- Closed the output-publication crash window by recording the exact staged WAV
  fingerprint before atomic commit. A later identical run can verify a
  published output and clean stale checkpoint data without reprocessing it.
- Included compressed decoder buffers, retained metadata, staged WAV bytes,
  and the checkpoint spool in the existing memory, temporary-space, and worker
  admission checks.

## Compatibility

- Ogg Opus, MP3, M4A/ALAC, and ADTS AAC remain on the whole-file path until a
  bounded decoder can preserve their granule, gapless, or edit-list timelines.
  VAD, loudness normalization, encoded streaming output, and other AI backends
  also remain on the normal path.
- `--stream` still requires filesystem input and output paths. The input must
  resolve to a regular WAV, FLAC, or Ogg Vorbis file, and the destination must
  be a WAV path. Normal non-streaming WAV stdin/stdout pipes remain available.
- The checkpoint PCM spool and staged WAV coexist during publication, so both
  count toward `--max-temp-space`. Private third-party allocations and
  allocator rounding remain outside cooperative byte-exact accounting.
- `--resume` without either `--batch` or `--stream` now fails explicitly
  instead of being silently ignored. Existing batch-resume behavior is
  unchanged.
- Because the denoize package version participates in the unchanged v3
  batch-resume recipe hash, v0.55 records are reported as `recipeChanged` after
  upgrading to v0.56. Existing outputs remain untouched unless `--force` is
  supplied. Regenerate once with `--force` to migrate the saved recipes;
  subsequent identical v0.56 runs skip normally.
