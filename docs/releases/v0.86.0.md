# denoize v0.86.0

v0.86.0 implements Stage 33: one stable, bounded scalar processing boundary for
C/C++, WebAssembly/Web Audio, Android, and iOS, with machine-readable capability
and lifecycle contracts and release evidence for every SDK package.

## Added

- Added C ABI v1 with opaque handles, fixed-width sized/versioned structures,
  stable status values, caller-owned interleaved `float32` buffers, exact
  in-place support, conservative preflight capacity reporting, copied
  diagnostics, unwind containment, creator-thread processor ownership, and a
  separately allocated cross-thread atomic cancellation token.
- Added frozen C and C++ header compilation, exact ABI layout/schema checks,
  live C smoke tests, old-header/new-library compatibility execution, and
  static/shared native packages for Linux x86-64, Windows x86-64, macOS Intel,
  and macOS Apple Silicon. The Windows package distinguishes the DLL import
  library from the independent static library.
- Added scalar finite/incremental WASM from the canonical native DSP source,
  with bounded calls/buffering, exact finish accounting, cooperative
  cancellation, a pinned `wasm-bindgen` package, and a Node smoke test.
- Added a cross-origin-isolated Web Audio host. A dedicated Worker owns WASM;
  two preallocated shared rings connect it to an AudioWorklet that observes the
  actual render quantum and performs no DSP, waits, network/filesystem I/O, or
  explicit per-render allocation. Finish drains queued input and the DSP tail;
  cancellation is explicitly non-draining.
- Added real cross-origin-isolated Playwright coverage in Chromium, Firefox,
  and WebKit. All three initialize Worker/WASM/AudioWorklet state and cancel;
  Chromium additionally observes a render quantum and completes finish/drain.
  Headless Firefox/WebKit initialization is not presented as deadline evidence.
- Added an optional WAM descriptor over the same Web Audio core. It remains
  host-matrix-gated and is not advertised as universally supported.
- Added an Android API-26+ Kotlin/JNI worker wrapper and release AAR for
  `arm64-v8a` and `x86_64`, pinned to JDK 17, AGP 9.3, Gradle 9.5, API 37, and
  NDK 28.2.
- Added an iOS-15+ Swift worker wrapper and release XCFramework for arm64 device,
  arm64 simulator, and x86-64 simulator slices.
- Added the shared closed mobile lifecycle: interrupt, background, memory
  pressure, and route change invalidate device-bound state; resume/route change
  require a freshly queried route, advance a checked generation, and rebuild.
- Added `denoize sdk capabilities` and `denoize sdk lifecycle`, plus compact and
  pretty JSON modes, Rust lifecycle APIs, four closed JSON schemas, package
  guides, the embedding guide, roadmap/research status, and version checks.
- Expanded release evidence from 25 to 32 primary installable artifacts and 32
  CycloneDX SBOMs. Tagged release jobs build, inspect, checksum, attest, and
  verify all four C archives plus Web, Android, and iOS SDK archives before
  publication.

## Safety and compatibility boundary

ABI v1 retains its exact structure sizes and symbol names. Future incompatible
layouts use separately named versions. Unknown sizes, versions, flags, reserved
fields, resource bounds, and wrong-thread calls fail closed. No Rust enum,
allocator, string, error, borrowed pointer, or panic crosses C. Token destruction
must be synchronized after all concurrent cancellation/reset calls complete.

All wrappers use the classical scalar backend; unavailable neural backends are
reported as unsupported. The C and mobile wrappers may allocate and therefore
must run on an application worker behind an app-owned preallocated callback
ring. SDKs do not open devices, request permissions, access a filesystem or
network implicitly, or download/install models.

## Deliberate limitations

- Web streaming requires cross-origin isolation and `SharedArrayBuffer`.
  Bounded ring operation does not imply a universal real-time deadline across
  browsers, operating systems, and devices.
- SIMD remains an optional detected optimization; scalar output is the
  compatibility oracle.
- The WAM descriptor is packaging, not promotion. General WAM support waits for
  lifecycle/state/deadline host evidence across Chrome, Firefox, and Safari.
- Android and iOS provide processing/lifecycle wrappers, not an audio-device or
  permission framework. Route and measured latency claims remain device/OS
  specific.
- ABI v1 exposes classical scalar finite/incremental processing. Rich runtime
  package-v2 tensor roles and neural restoration backends require later explicit
  ABI versions rather than silent substitution.

## Release verification

The release workflow validates the complete Rust workspace and SDK-specific
strict clippy checks, all 93 JSON contracts, C/C++ consumers, deterministic ABI
mutation sequences under pinned AddressSanitizer-backed libFuzzer, Node/Web
transport tests, both Android ABIs, an API-35 x86-64 instrumentation run, every
iOS slice, macOS and iPhone-simulator Swift tests, generated CLI reference,
exact version metadata, crates.io contents, 32 release artifacts/checksums,
recoverable application updates, 32 SBOMs, real browser
initialization/cancellation across three engines, Chromium finish/drain,
Worker-loss fail-closed handling, and tagged-workflow provenance before
publication.
