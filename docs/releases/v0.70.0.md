## Highlights

- Added a signed recoverable application-update transaction shared by the Rust
  library, `denoize update`, and the Desktop Application updates page. The
  manifest binds channel, source commit, platform artifact, CycloneDX SBOM,
  Sigstore provenance, compatibility, and rollback policy.
- Added bounded authenticated online downloads and complete offline `.dub`
  bundles. Read-only check, inspect, and dry-run operations precede explicit
  apply; state keeps the candidate and exact last-known-good installation in
  private synchronized slots.
- Added startup-health confirmation, bounded attempt/deadline recovery, manual
  offline recovery, a monotonic anti-rollback floor, equivocation detection,
  and bounded path/token-free durable diagnostics.
- Desktop activation now consumes only a verified slot and uses the native
  package path for macOS app bundles, AppImage, deb, NSIS, and MSI. Startup does
  not perform an online check or silent installation.
- Added nine Draft 2020-12 update schemas and release generation/verification
  for six platforms, transitions from both v0.68.0 and v0.69.0, 12 `.dub`
  bundles, individual referenced SBOMs, and a separate update-asset attestation.

## Compatibility

- The v1 update state and reports are new. Unknown or future versions fail
  without changing an existing installation or state root.
- v0.70.0 accepts exact update transitions from v0.68.0 and v0.69.0. Recovery
  may activate either authenticated last-known-good package but never lowers
  the recorded v0.70.0 anti-rollback floor.
- The standalone CLI controls the portable transaction and does not invoke a
  privileged OS installer. The official Desktop supplies the platform
  activation layer; other launchers can consume `active_update_target`.
- Because the denoize package version participates in the unchanged v3
  batch-resume recipe hash, v0.69.0 records are reported as `recipeChanged`
  after upgrading. Existing outputs remain untouched unless `--force` is
  supplied.

## Security boundary

- Only credential-free HTTPS is accepted for signed online sources. Redirects,
  response length, staging bytes, artifact bytes, evidence bytes, and JSON
  sizes are bounded; a corrupt or mismatched download is discarded before
  no-clobber publication.
- Apply synchronizes candidate and rollback slots before the atomic state
  commit. Activation failure restores last-known-good state; candidate startup
  corruption, timeout, or excessive attempts triggers the same offline path.
- Cleanup is confined to validated private updater-owned directories and never
  deletes the active or only recoverable slot. Health tokens and local paths
  are not emitted in durable diagnostics.
